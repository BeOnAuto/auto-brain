# @on.auto/json-schema

The runtime's one JSON Schema compiler: it compiles the input, output and view schemas a person writes in a definition of a computation, recall, interaction or prediction function and the answer schema of a reasoning function, and checks values against them. It compiles no tool's input schema: reasoning reads only the size and nesting of one, with `boundedJsonSchema`, before it says what a provider may refuse in it, the tool-servers bridge bounds the nesting of an OpenAPI document with `nestedDeeperThan` and the size of a tool's input schema with `jsonSchemaLimits` and `utf8Bytes`, and the server it calls checks the arguments itself. It sits below every package that reads a schema, so [`@on.auto/definitions`](../definitions/README.md) and the capabilities import it and it imports nothing of theirs: only `effect`, whose JSON Schema importer it compiles with.

## Compiling a schema

`compileJsonSchema(document, { what, nesting, further })` checks a JSON Schema's shape, size, references and loops, and compiles a validator that answers issues with JSON pointers; `what` names the schema in its issues and `nesting` bounds the values it validates. `further`, optional, is a check of what a schema cannot say, such as an order or a sum, which the output shapes of `@on.auto/definitions` give: it reads every value that is JSON within the nesting, and its issues follow the schema's within the same bound. `jsonSchemaLimits` are its bounds, a schema of at most 65,536 bytes as JSON nested at most 64 levels with at most 20 issues named, `boundedJsonSchema` its first check alone, of the size and nesting of a schema, which reasoning also runs on the input schema of a tool, and `shapeIssues`, `isKnownKeyword` and the helpers of `json-bounds.ts`, `pointerOf`, `utf8Bytes`, `nestedDeeperThan`, `boundedIssues`, `hiddenIssues` and `mostIssues`, the checks it is built from (`src/document`).

The dialect is JSON Schema 2020-12, or draft-07 when the schema says so or keeps `definitions` without `$defs`, bounded on purpose for documents a person writes: a reference is local, `#/$defs/<name>` or `#/definitions/<name>`, and `pattern`, `patternProperties`, `if`, `then`, `else`, `contains`, the dependent keywords, `unevaluatedItems`, `unevaluatedProperties`, `additionalItems` and the dynamic and recursive anchors are refused with words that say why (`src/document/schema-shape.ts`); a definition that leads into a loop of `$ref`, `allOf`, `anyOf` or `oneOf` with no property or item in between is refused at its pointer (`src/document/reference-loops.ts`).

A compiled schema is `{ document, what, validate, issuesOf }`. `validate(value)` answers the value, or its issues in the words of the validator, each at its JSON pointer. `issuesOf(value)` answers the same issues, none for a value the schema takes, and gives each the rule of the schema it breaks as its `breach` (`src/document/found-issues.ts`): `kind`, for a value of another type or choice than the schema allows, a whole number among them; `missing`, for a required field or item that is not there; `unexpected`, for a field or item the schema does not allow, or a value where it allows none; and `bound`, with the keyword and its value, such as `{ minLength: 6 }`, for `minLength`, `maxLength`, `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf`, `minItems`, `maxItems`, `uniqueItems`, `minProperties` and `maxProperties`. An issue no keyword names, such as a value two branches of `oneOf` take, a value too deep, or one the further check finds, has no breach. The words a person reads are made from it by `wordedIssuesOf` of `@on.auto/definitions`, which reads the schema; this package says which rule broke and knows no words of a field.

## Checking a value

`schemaCheckOf(schema, { what, nesting, further })` is a check of a value that names at most three of its issues, the further check's among them, and `issuesDetail(issues, what)` the one wording of them, each at its pointer or as the output or the view itself at the root (`src/checking`). The checked worker of `@on.auto/definitions` checks the outputs and views of computation and recall functions with them, and the interaction capability words a refused answer with `issuesDetail`.

## Source

`src/document` holds the compiler and its bounds, and `src/checking` the check of a value. The tests beside them pin the dialect and the hostile schemas it refuses.
