# Brain terminology migration report

This implements the v1 terminology brief across `auto-brain` and the sibling `on.auto` site. The maintained reference is [Brain terminology](../concepts/terminology.md). The runtime work started from `ffdfa54666c34e6b72d0135550c43c3737b58266`, including the merged workflow host and local quick-start changes. No production data, deployed service, package release or publication was changed.

## Implemented

- Parsed reasoning configuration uses `ReasoningFunctionDefinitionDocument`; their factory and options are `makeReasoningFunctionAdapter` and `ReasoningFunctionAdapterOptions`. The server and tests consume the new names.
- Parsed workflow documents use `WorkflowDefinitionDocument`; the adapter uses `makeWorkflowAdapter` and `WorkflowAdapterDependencies`. Workflow calls, which can also target extension adapters, use `DefinitionRunRequest`, `DefinitionRunResult`, `RunDefinition`, `definitionCalls` and `definitionRunResultOf`.
- Stored definitions use `BrainFunctionDefinition`, currently covering `ReasoningFunctionDefinition`, and `WorkflowDefinition`. Their runs use `FunctionRun` and `WorkflowRun`. Type guards narrow decoded records by the existing wire discriminators; unknown adapters and planned kinds are not accepted as implemented function types. Generic `Definition` and `Run` records still serve shared persistence and extension adapters. The parsed document types are separate from these stored records; `WorkflowDefinitionDocument` remains a `JsonObject` validated by the existing parser. `DefinitionSummary`, `PreparedDefinition` and `RunContext` replace the equivalent internal spec/execution type names.
- `packages/specs/src/primitive/function-terminology.ts` centralizes `BrainFunctionKind`, the exact five category labels and descriptions, countable resource names and the confirmed legacy mapping. Workflows and Dream are absent from the function-kind list. The reasoning adapter and error presentation consume this metadata.
- `pnpm docs:taxonomy` generates `docs/assets/brain-functions.json` from those public runtime exports. `docs:taxonomy:check` rejects a missing or stale generated asset without rewriting it. The site imports this asset through its existing source snapshot and watch pipeline, with the source revision and draft status recorded. Its own metadata supplies only availability wording. Local watch regenerates the asset when runtime metadata changes; labels and descriptions have one authored source.
- Tool titles, schemas, agent instructions, human-readable results and applicable errors distinguish definitions from runs. Generated schemas keep their stable identifiers and field names.
- The terminology reference covers definitions, versions, runs, steps, attempts, triggers, assets, prediction lifecycle, Studio wording and category positioning. Current docs and examples distinguish supported behavior from planned capabilities. The README retains its runnable quick start.
- Existing heading fragments remain available after visible wording changes. The site preserves its learning-oriented documentation navigation; its function overview uses Reasoning, Interaction, Prediction, Recall and Computation in that order, with workflows separate.
- The website migration is detailed in `on.auto/TERMINOLOGY_MIGRATION.md`. The Humanizer pass kept prose direct without changing the approved names or adding capabilities.
